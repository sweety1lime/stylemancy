# Стилемантия — квест-тренажёр по вёрстке

Игра для закрепления HTML, CSS и JavaScript: студент пишет настоящий код, движок сравнивает результат с эталоном и объясняет ошибки по-русски.

**Играть:** https://sweety1lime.github.io/stylemancy/ (без входа — гостем)

Как устроены мир, уровни и проверка — в [docs/design.md](docs/design.md).

Статус: игру прошли преподаватель и несколько знакомых, урок с группой ещё впереди. Уровни пока не проверены преподавателем, поэтому в формулировках и подсказках возможны шероховатости.

## Запуск

```bash
npm install
npm run dev      # игра на http://127.0.0.1:5173
npm test         # автотесты; перед первым запуском: npx playwright install chromium
npm run build    # сборка сайта в папку dist/
npm run lint
```

Автотесты аккаунтов работают с настоящей базой Supabase: создают учителя, класс и студента и в конце удаляют их. Без интернета их можно пропустить: `$env:OFFLINE=1; npm test`.

Скриншоты сцен всех уровней (до и после решения) для проверки глазами — в `test-results/gallery/`:

```powershell
$env:GALLERY=1; npx playwright test gallery   # PowerShell
$env:GALLERY="box-,pos-"; npx playwright test gallery   # только уровни, чей id начинается так
```

## Как добавить уровень

1. Скопировать соседний файл в `src/levels/<район>/`, например `flex-03.ts` → `flex-04.ts`, и поменять `id`, реплики, задачу, стартовый код, эталон и подсказки.
2. Добавить уровень в список `levels` в `src/levels/<район>/index.ts`.
3. Запустить `npm test`: тест проверит, что эталон проходит уровень, стартовый код — нет, а цели не выходят за край сцены.

Цели на сцене рисовать не нужно — они строятся из эталонного решения.

В репликах, задаче и подсказках `обратные кавычки` превращаются в код. Код с обратной кавычкой внутри берут в двойные: ``` `` `${price} монет` `` ```, а саму кавычку показывают так: ``` `` ` `` ```.

- **Адаптив:** `check.viewports: [360, 720]` — сцена показывается и проверяется в нескольких «зеркалах» этой ширины.
- **Обязательный приём:** `require: [{ pattern, message }]` — без него решение не засчитается, даже если всё на месте (так уровень про `fr` не решить пикселями). Студент увидит это сообщение, когда предметы уже стоят на местах.
- **Селекторы и каскад:** `check.style: 'color'` — сравнивается не место предмета, а значение свойства: какие предметы нашёл селектор и чьё правило победило. `check.hover: '.firefly'` — второе зеркало «Под мышкой», где эти элементы считаются наведёнными мышью. `lockedCss` — чары Лорда Дефолта: стили, которые студент видит, но не меняет; они стоят после его кода.
- **Слои:** `check.stacking: true` — проверяется ещё и кто кого заслоняет (`z-index`): в центре каждого предмета смотрим, чей он сверху. Спрятанный через `visibility: hidden` предмет проверка отличает от убранного через `display: none` сама.
- **HTML-уровень** описывается через `defineHtmlLevel`: стартовая и эталонная разметка и цели — что должно найтись в разметке студента (`selector`, `count`, `text`, `contains`; `clean` — «ни одной ошибки», `doctype` — первая строка). `document: true` — студент пишет документ целиком, с `<head>`.
- **JS-уровень** описывается через `defineJsLevel`: стартовый и эталонный скрипт. `check.output: true` — сравнить всё, что сказал Оракул (`console.log`, `alert`, вопросы `prompt`), строка за строкой; `check.vars` — колбы-переменные, у которых сравниваются значение и тип. `runs` — запуски с разными ответами на `prompt`: код должен сработать для каждого «гостя». `require` и `reject` — обязательные и запрещённые приёмы, комментарии в коде не считаются.
- **«Алхимия функций»** — JS-уровень с `calls`: вызовы-флаконы вроде `'double(5)'`. После скрипта каждый вычисляется, и что он вернул, сравнивается с эталоном — значение и тип. Массивы и объекты сравниваются по содержимому, у объектов порядок полей не важен.
- **«Путь героя»** — JS-уровень с `dungeons`: подземелья, по которым код ведёт героя. Карта — строки одинаковой длины: `#` стена, `.` пол, `g` кристалл, `b` баг, `E` выход, `1`–`9` табличка с числом, `> < ^ v` — герой и куда он смотрит. Уровень пройден, когда в каждом подземелье герой у выхода и все кристаллы собраны. `maxLines` — звезда за краткость: код длиннее засчитывается, но с одной звездой меньше. Тест сам проверит, что на карте один герой, до выхода можно дойти, а эталон укладывается в `maxLines`.
- **«Оживление»** — JS-уровень с `page` и `steps`: страница (`html`, своё оформление `css`, а `watch` — какие элементы сравнивать; подпись в сообщениях берётся из `data-name`) и сценарий. Шаг — что сделать со страницей: `type: ['.code', '4217']`, `click: '.try'` (`times` — сколько раз), `submit: '.form'`; шаг без действий — сразу после запуска. После каждого шага у отмеченных элементов сравниваются с эталоном классы, текст, значение поля, видимость и `disabled`. Подпись шага — цель в списке, часть до тире — начало сообщений о промахах. Страница живёт в iframe без доступа к игре; форма без `preventDefault` «перезагружает» её, а `Math.random` в проверке всегда начинается с 0.42. `download: 'game.html'` — под сценой кнопка «Скачать игру».

## База данных

Supabase: таблицы, правила доступа и функции — в `supabase/migrations/`. Новую миграцию выполняют в панели Supabase → SQL Editor (вставить файл целиком → Run). Адрес проекта и публичный ключ — в `src/lib/config.ts`: они не секретные, данные защищают правила доступа в базе. Секретный ключ сайту не нужен и в репозиторий не попадает.

## Устройство

- `src/engine` — движок: разбор и проверка CSS (`cssParse`, `lint`), сцена и сравнение с эталоном (`scene`), итог и звёзды (`evaluate`); для HTML — разбор разметки с объяснениями ошибок (`htmlLint`) и цели уровня (`htmlCheck`); для JS — разбор кода на парсере acorn (`jsLint`), запуск в фоновом потоке (`jsRun`, `jsWorker.js` — там же ходит герой «Пути героя»), сравнение вывода и колб с эталоном (`jsCheck`) и карты подземелий (`dungeon`); страницы Города Механизмов — документ страницы со стражем циклов (`pageHarness`, `loopGuard`), запуск в изолированном iframe (`pageRun`) и проверка по шагам (`pageCheck`)
- `src/levels` — районы и уровни (только данные): земли Каскадии и Скриптории; `src/levels/shared` — общие предметы сцен (кристаллы, стёкла, небо, кладка и часовые крепости, предметы леса, которые красит color) и списки разрешённых свойств
- `src/game` — прогресс, аккаунты и синхронизация (`auth`, `sync`), кто в какую землю может войти (`access`: дверь `<script>`), панель учителя (`teacher`), заклинания, настройки компьютера (`settings`: звук и эффекты) и 8-битные звуки (`sound`)
- `src/components` — интерфейс; эффекты сцены (перелёты, искры, магический круг) — `sceneFx`
- `tests` — автотесты Playwright

## Решения и компромиссы

- **Проверка смотрит на результат, поэтому у района свои правила.** На островах разрешён только Flexbox, иначе задачу обходят через `margin` или `position`. Если уровень учит приёму (`fr`, `repeat()`, `margin: 0 auto`), он требует именно его, но говорит об этом, только когда предметы уже стоят на местах.
- **Код студента не видит игру.** Основы JS выполняются в Web Worker, страницы Города Механизмов — в iframe с `sandbox` без `allow-same-origin`. Зависший цикл останавливается сам: в воркере по таймеру, на странице через страж, вставленный в каждый цикл.
- **Студенты без почты.** Служебный адрес собирается из хеша ника и кода класса в зоне `.invalid`: она зарезервирована стандартом, и письмо туда уйти не может. Ник не обязан совпадать с ФИО, о несовершеннолетних в базе хранится минимум.
- **Права проверяет база, а не сайт.** Таблицы закрыты правилами RLS, сброс пароля и удаление студента — функции базы с проверкой «это твой ученик». Публичный ключ Supabase лежит в коде, секретный сайту не нужен.
- **Учебный компьютер общий.** Гость и каждый аккаунт хранят прогресс в браузере под своими ключами. При входе прогресс сливается с сервером, и по каждому уровню берётся лучший результат.
- **Весь класс выходит в интернет с одного IP**, поэтому лимиты входа в Supabase подняты.
- **GitHub Pages и адреса через `#`.** Хостингу не нужна настройка сервера, а бесплатный проект Supabase не засыпает благодаря ежедневному запросу из `.github/workflows/keep-alive.yml`.
- **Шрифт Tiny5.** В Pixelify Sans кириллическая «д» похожа на «а», а заглавной «П» нет вовсе. Press Start 2P оказался слишком широким.
- **Название проверено на совпадения.** «Каскадия» уже занята настольной игрой, у авторов Flexbox Froggy есть CSS-игра Cascade, поэтому продукт называется «Стилемантия», а Каскадия осталась местом в сюжете.
- **Решения уровней видны в коде сайта.** Для тренажёра это допустимо: списывая, ученик обманывает только себя.
- **На уроке тихо.** Звук по умолчанию выключен, а при системной настройке «уменьшить движение» включаются лёгкие эффекты.
