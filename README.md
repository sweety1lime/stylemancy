# Стилемантия — квест-тренажёр по вёрстке

Игра для закрепления HTML и CSS: студент пишет настоящий CSS, движок сравнивает результат с эталоном и объясняет ошибки по-человечески. План, решения и статус — в [PLAN.md](PLAN.md).

## Запуск

```bash
npm install
npm run dev      # игра на http://127.0.0.1:5173
npm test         # автотесты; перед первым запуском: npx playwright install chromium
npm run build    # сборка сайта в папку dist/
npm run lint
```

Автотесты аккаунтов работают с настоящей базой Supabase: создают учителя, класс и студента и в конце удаляют их. Без интернета их можно пропустить: `$env:OFFLINE=1; npm test`.

Скриншоты сцен всех уровней (до и после решения) для проверки глазами — в `test-results/gallery/`:

```powershell
$env:GALLERY=1; npx playwright test gallery   # PowerShell
$env:GALLERY="box-,pos-"; npx playwright test gallery   # только уровни, чей id начинается так
```

## Как добавить уровень

1. Скопировать соседний файл в `src/levels/<район>/`, например `flex-03.ts` → `flex-04.ts`, и поменять `id`, реплики, задачу, стартовый код, эталон и подсказки.
2. Добавить уровень в список `levels` в `src/levels/<район>/index.ts`.
3. Запустить `npm test`: тест проверит, что эталон проходит уровень, стартовый код — нет, а цели не выходят за край сцены.

Цели на сцене рисовать не нужно — они строятся из эталонного решения.

- **Адаптив:** `check.viewports: [360, 720]` — сцена показывается и проверяется в нескольких «зеркалах» этой ширины.
- **Обязательный приём:** `require: [{ pattern, message }]` — без него решение не засчитается, даже если всё на месте (так уровень про `fr` не решить пикселями). Студент увидит это сообщение, когда предметы уже стоят на местах.
- **Селекторы и каскад:** `check.style: 'color'` — сравнивается не место предмета, а значение свойства: какие предметы нашёл селектор и чьё правило победило. `check.hover: '.firefly'` — второе зеркало «Под мышкой», где эти элементы считаются наведёнными мышью. `lockedCss` — чары Лорда Дефолта: стили, которые студент видит, но не меняет; они стоят после его кода.
- **Слои:** `check.stacking: true` — проверяется ещё и кто кого заслоняет (`z-index`): в центре каждого предмета смотрим, чей он сверху. Спрятанный через `visibility: hidden` предмет проверка отличает от убранного через `display: none` сама.
- **HTML-уровень** описывается через `defineHtmlLevel`: стартовая и эталонная разметка и цели — что должно найтись в разметке студента (`selector`, `count`, `text`, `contains`; `clean` — «ни одной ошибки», `doctype` — первая строка). `document: true` — студент пишет документ целиком, с `<head>`.

## База данных

Supabase: таблицы, правила доступа и функции — в `supabase/migrations/`. Новую миграцию выполняют в панели Supabase → SQL Editor (вставить файл целиком → Run). Адрес проекта и публичный ключ — в `src/lib/config.ts`: они не секретные, данные защищают правила доступа в базе. Секретный ключ сайту не нужен и в репозиторий не попадает.

## Устройство

- `src/engine` — движок: разбор и проверка CSS (`cssParse`, `lint`), сцена и сравнение с эталоном (`scene`), итог и звёзды (`evaluate`); для HTML — разбор разметки с объяснениями ошибок (`htmlLint`) и цели уровня (`htmlCheck`)
- `src/levels` — районы и уровни (только данные); `src/levels/shared` — общие предметы сцен (кристаллы, стёкла, небо, кладка и часовые крепости, предметы леса, которые красит color) и списки разрешённых свойств
- `src/game` — прогресс, аккаунты и синхронизация (`auth`, `sync`), панель учителя (`teacher`), заклинания, настройки компьютера (`settings`: звук и эффекты) и 8-битные звуки (`sound`)
- `src/components` — интерфейс; эффекты сцены (перелёты, искры, магический круг) — `sceneFx`
- `tests` — автотесты Playwright
